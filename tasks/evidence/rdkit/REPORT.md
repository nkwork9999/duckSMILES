# Chemob / DuckSMILES と RDKit — 2026-10-17

## 結論

LogPのSMARTS照合で毎回作っていた隣接情報を分子ごとに再利用し、測定対象の計算結果を変えずに高速化した。速度は改善したが、**RDKit互換性ゲートは未合格**。質量計算などの不一致を修正してから実務利用を判断する必要がある。

## 速度

Apple Silicon Mac、RDKit 2026.03.6、同じ1,000行（997種類）、12記述子＋分子式。新しい分子を行ごとに解析し、重複キャッシュなし。JSON直列化・復号まで含む。64行ずつ、ウォームアップ後3回、修正前・修正後・RDKitの順番を入れ替えた。他のビルドを終えてから測定した。

| 経路 | 中央値 | 3回の範囲 |
|---|---:|---:|
| DuckSMILES 修正前 | 3,874 ms | 3,790–4,069 ms |
| DuckSMILES 修正後 | 592 ms | 568–651 ms |
| RDKit | 701 ms | 488–723 ms |

修正前比6.54倍。RDKitとの範囲は重なっており、普遍的な優位性は主張しない。Mac全体では他の作業が動いており、負荷平均も保存している。これはPythonからC ABIを呼ぶホスト測定であり、iPhone実機・画面描画の速度ではない。前回の「8分子を繰り返す」測定とはデータが異なるため、直接の前後比較には使わない。

生データ: [paired-timing.json](paired-timing.json)。実行コード: [paired_rdkit_timing.py](../../benchmarks/paired_rdkit_timing.py)。

## 精度と受理状態

RDKit付属NCI `first_5K.smi` の4,999行（4,900種類）＋20件の境界入力、計5,019行。除外せず全行を照合した。RDKitはsanitize有効、明示Hを保持、TPSAはN/O、回転可能結合はStrict。

- 両方が受理: 5,002行。このうち全項目が許容値内で一致: 3,602行。
- 値または分子式の不一致: 1,400行。
- 受理状態の差: 10行（DuckSMILESだけ受理8、RDKitだけ受理2）。後者の2件は長さ・対応文法によるDuckSMILESの意図的な制約も含む。
- 両方が不正入力と判定: 7行。
- 高速化前後で全分子のRDKit差分リストは同一。さらに10,000行の出力全体を完全一致で確認した。

| 項目 | 不一致行数 |
|---|---:|
| 分子量 | 1,215 |
| 精密質量 | 280 |
| HBA | 6 |
| TPSA | 11 |
| LogP | 32 |
| sp³炭素割合 | 1 |
| 分子式の文字列 | 21 |
| 重原子数・結合数・電荷・成分数・HBD・回転可能結合 | 各0 |

複数項目で不一致になる分子があるため、項目別件数の和は分子数ではない。分子式には元素の並び順だけの差も含む。許容差は分子量0.005、精密質量0.00001、TPSA/LogP 0.000001、sp³割合0.000000001、整数項目と分子式は完全一致。

### 確認された問題

- 原子量表の数値差: 硫黄を含む分子で分子量がずれる例がある。
- 未収載元素の寄与が0扱いになる: Th、Ce、Hg等で大きい誤差。例: Hgを2個含む分子の精密質量234.1103に対しRDKit638.0516。
- 既存の質量計算は元素数から足し合わせるため、同位体指定・イオンの電子質量補正を反映しない。
- HBA/TPSA/LogPには原子型・芳香族性等を個別に調べる必要がある差が残る。
- RDKitがsanitizeで拒否する8構造もDuckSMILESは受理する。受理していることを化学的妥当性の証明に使わない。

差分原本: [rdkit-differences.json](rdkit-differences.json)。`compare_rdkit.py --strict` はこれらが残る間は終了コード1。内部の727テスト合格とRDKit互換性テストの不合格は別の結果として保存した。

## 10,000行の入出力

NCIの2周＋不正・空欄の2行で10,000行。10,000種類の独立した化合物ではない。名前には日本語・カンマ・引用符・改行を混ぜた。

実際のSwift `Workbench.importText` → Rust計算 → `Workbench.exportCSV` → `CompoundImport.parse` をmacOSホストから実行。Python標準CSV実装でも全行の名前・SMILES・順序、全12数値列、分子式、不正入力の空欄出力を照合し、成功した。SMILESの前後空白は既存の取込仕様に従い除去する。

修正前には439,251 bytesの入力が1,552,597 bytesの結果CSVになり、1MiB上限のため再読込できなかった。アプリ側のファイル上限を8MiBへ統一し、10,000行上限を維持した。単一SMILESがネイティブの4,096 bytes制約を超える場合はその行だけを要確認にし、他の行を巻き込んでバッチ全体を拒否しない。原本は保持する。C ABI自体の1MiB/10,000行制約は変更していない。

[bulk-io-summary.json](bulk-io-summary.json) と [bulk-io-independent-check.json](bulk-io-independent-check.json) を参照。上限超過10,001行、C ABI入力1MiB超過、不正UTF-8、null入力、短い出力バッファに書き込まないことも確認した。

2. 不一致のHBA/TPSA/LogP原子型・芳香族性を分子ごとに修正する。
