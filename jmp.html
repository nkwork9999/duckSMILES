JMP and JMP Pro coverage

This page summarizes the versioned comparison between duckSMILES' CPU analytics and the published JMP and JMP Pro 19.2 capabilities. The feature matrix tracks 552 entries from 14 capability areas, supplementing the official listings with selected details from the 19.2 reference. Entries include methods, capabilities, and options at different levels of detail. Use the SQL guide for current APIs and the original comparison record for historical checkpoints and acceptance details.

October 24, 2026 checkpoint

The checkpoint recorded 279 analytics functions and 430 extension-wide SQL overloads. The matrix classified 287 entries as partially covered, 197 as unimplemented, 37 as existing DuckDB functionality, six as covered by earlier limited contracts, 17 as GUI operations, four as external extensions, and four as separate products.

PLS2 and PLS-DA

Multivariate PLS2 and PLS-DA expose fit and prediction operations, NIPALS/SVD and SIMPLS, training-set scaling by sample standard deviation, and variable-importance scores. Regression can return approximate conditional prediction intervals. PLS-DA returns predictions for the encoded response indicators. Validation supports explicit folds and roles, including selection of a zero-component model. Each fold learns its transformation on training rows. Held-out test rows stay out of selection and the final fit. The contract defines the Root Mean PRESS calculation and aggregation. Model format 2 preserves residual standard deviation and supports loading format 1.

Gaps include missing-data fitting, random stratification, repeated and nested tuning, the van der Voet test, bootstrapping, and comparison against JMP itself.

Zero-inflated regression

The validated API fits zero-inflated binomial, beta-binomial, Poisson, negative binomial, and gamma models and predicts from saved models. The contract covers unpenalized maximum likelihood, shared zero-inflation probability, integer frequencies, numeric fixed effects, observed-information and HC0 covariance. Remaining differences include regularization and selection, fractional trial counts, missing or categorical roles, and JMP-specific covariance conventions.

Scope and edition

The matrix covers CPU numerical methods, including static report output where an acceptance contract exists. It tracks separate products such as JMP Live and JMP Clinical separately. Marketplace extensions are labeled as external. DuckDB supplies relational aggregation, joins, PIVOT, and UNPIVOT.

The edition mapping uses the JMP Pro label and the versioned product documentation to identify restrictions. Availability can depend on the option and platform.

Validation and reproducibility

Development checkpoints record the exact source and tests at each stage. The October 24 checkpoint recorded 1,400 passing Rust tests, two pre-existing ignored tests, 21 native SQL cases, 637 assertions, and 430 runnable catalog examples. The PLS validation and selection evidence compares 6,684 numerical items and 28 invalid-input NULL cases against independent references across the C ABI and native DuckDB. The earlier PLS fit/prediction evidence compares 7,220 numerical results and 34 invalid-input NULLs on those same public paths.

Use the version-matched native DuckDB build when reproducing SQL and catalog tests. Compare individual inputs, outputs, tolerances, and scope against the JMP feature matrix and the evidence for the particular API.
